# Project Zomboid Manager

Cross-platform desktop launcher and save backup manager for Project Zomboid (Windows, Linux, macOS).

Built with Go and [Fyne v2](https://fyne.io/).

## Features

- List Project Zomboid saves with metadata (game version, last played, size, backup count)
- Manual backups (ZIP or folder copy) with optional labels
- Auto-backup before launching the game (only when save changed; configurable retention)
- Atomic restore with optional safety backup of current save
- Three launcher integration modes: from app, desktop shortcut, Steam Launch Options
- Dedicated progress window when launching from Steam (with skip option)

## Build

Requires Go 1.26+ and a C compiler (Fyne uses CGO).

```bash
go build -ldflags "-X main.Version=$(git describe --tags --always 2>/dev/null || echo dev)" -o bin/pz-manager ./cmd/manager
```

For platform-specific packaging (icons, .app bundles, .exe metadata):

```bash
go install fyne.io/tools/cmd/fyne@latest
fyne package -os darwin   # or linux / windows
```

Cross-compiling Fyne apps from macOS/Linux to Windows etc. requires platform-specific C toolchains; the easiest workflow is to build natively on each OS or use CI runners.

## Run

```bash
./bin/pz-manager                      # GUI mode
./bin/pz-manager --auto-launch        # auto-backup + launch game (CLI)
./bin/pz-manager --version            # print version
```

For Steam integration, in Steam → Properties → Launch Options:

```
"<absolute-path-to-pz-manager>" --auto-launch -- %command%
```

## Releases

The project uses GitHub Actions for distribution. See `.github/workflows/`:

- **`ci.yml`** — runs on every push / pull request to `main`. Verifies `go vet`, `go test`, and a Linux build. Catches regressions before tagging.
- **`release.yml`** — runs on tags matching `v*`. Packages with `fyne package` for Linux amd64, macOS arm64, and Windows amd64 on native runners (Fyne requires CGO so cross-compilation is impractical), producing platform-native bundles with embedded icons (`.app` with `.icns`, `.exe` with ICO resource, `.tar.xz` with `.desktop` + pixmap). Then publishes a GitHub Release with the bundles attached.

### How to cut a release

```bash
# 1. Tag locally (annotated tag with notes)
git tag -a v0.2.0 -m "Description of what changed"

# 2. Push the tag
git push origin v0.2.0
```

The `release.yml` workflow picks up the push, runs the matrix build, and creates the GitHub Release. Pre-releases (tags containing `-`, e.g. `v0.2.0-rc1`) are marked as such automatically.

Released artifacts:

- `pz-manager-linux-amd64.tar.xz` — extract, run binary or install via included Makefile (places `.desktop` entry + icon pixmap)
- `pz-manager-darwin-arm64.app.zip` — unzip, drag `Project Zomboid Manager.app` to Applications. Signed with Developer ID + notarized by Apple, so first launch works normally.
- `pz-manager-windows-amd64.exe` — double-click. Unsigned: SmartScreen warning on first run.

The version printed by `pz-manager --version` is injected at build time via `GOFLAGS="-ldflags=-X=main.Version=$GITHUB_REF_NAME"` (full tag including any `-rc` suffix). The bundle metadata version (Info.plist `CFBundleShortVersionString`, Windows file properties) is the strict X.Y.Z form passed to `fyne package --app-version`.

## Website

A public landing page lives at `https://pz-manager.pages.dev/` (or the custom domain configured in Cloudflare). Source in `web/` (Hugo project with own layouts, no external theme).

It is rebuilt by `.github/workflows/pages.yml` on every `release: published` event, on `workflow_dispatch`, and on pushes to `main` touching `web/`. The workflow:

1. Installs Hugo Extended (pinned version)
2. Queries the GitHub Releases API and writes `web/data/releases.json`
3. Runs `hugo --minify`
4. Deploys `web/public/` to Cloudflare Pages via Wrangler

### One-time setup

1. **Create a Cloudflare Pages project** (Direct upload model): Cloudflare dashboard → Workers & Pages → Create → Pages → Direct upload → name `pz-manager`. Skip the initial deploy — the workflow populates it.
2. **Create a Cloudflare API token** with permission `Account · Cloudflare Pages · Edit`. Profile → API Tokens → Create Token → "Edit Cloudflare Pages" template.
3. **Add two GitHub repo secrets** (Settings → Secrets and variables → Actions):
   - `CLOUDFLARE_API_TOKEN` — the token from step 2
   - `CLOUDFLARE_ACCOUNT_ID` — visible in the right sidebar of any Cloudflare dashboard page
4. **(Optional) Custom domain:** Cloudflare Pages project → Custom domains. DNS-only, no code change.

### Local development

Requires Hugo Extended (`brew install hugo` on macOS, or download from https://github.com/gohugoio/hugo/releases).

```bash
cp web/data/releases.example.json web/data/releases.json   # one-time, sample data
hugo --source web serve
# open http://localhost:1313/
```

`web/data/releases.json` is gitignored (real data is generated by CI). The example file gives you something to render against locally.

### Tests

Unit tests for the OS-detection JS run in the browser:

```bash
hugo --source web serve
# open http://localhost:1313/js/tests.html
```

All assertions must be green before publishing site changes.

## Project structure

```
.github/workflows/          # CI + release pipelines
cmd/manager/                # entrypoint, CLI args, DI
internal/
  domain/                   # core types: Save, Backup, GameInstance (no I/O)
  storage/                  # filesystem ops: scan, ZIP, restore, retention
  platform/                 # OS-specific paths and process launching
  launcher/                 # auto-launch flow orchestration
  config/                   # settings.json (atomic write + migration)
  ui/                       # Fyne views, dialogs, progress window
docs/superpowers/
  specs/                    # design spec
  plans/                    # implementation plan
```
